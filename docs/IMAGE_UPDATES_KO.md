# 이미지 데이터 갱신 (7.2.0)

7.2.0 DLL을 한 번 설치해야 한다. 7.1.x DLL에는 이미지 교체 consumer가 없으므로
이미지 파일만 GitHub에 추가해도 적용되지 않는다. 설치 파일은 [7.2.0 릴리스](https://github.com/kekwkekw/gctrans/releases/tag/v7.2.0)를 따른다.

## 데이터와 표시 경로

`manifest.json.images`는 `images.json` 원본 UTF-8 바이트의 SHA-256이다.
카탈로그의 각 항목은 `kind`, `name`, `width`, `height`, `file`, `sha256`, `bytes`를 가진다.
PNG 파일명은 `images/<sha256>.png`이며 원본과 같은 크기여야 한다.
종류·이름·크기의 exact 조합이 표시 대상이다. 같은 이름과 크기가 다른 화면에도 쓰이는지
원본 자산을 확인한 뒤 등록한다. 경로나 URL을 임의 실행하는 기능은 없다.

시작 시 기존 번역 manifest 확인 뒤 변경된 카탈로그와 필요한 PNG만 내려받는다.
카탈로그 해시, PNG 해시·바이트 수·크기를 확인하고 모든 파일이 준비된 뒤 카탈로그를 교체한다.
실패하거나 시간이 초과되면 기존 카탈로그를 유지한다. 첫 설치에 이미지 캐시가 없으면 원본이 표시된다.
오프라인에서는 검증된 로컬 파일을 사용한다. 실행 중 원격 변경을 즉시 적용하지 않으며 재시작이 필요하다.

Unity UI callback에서 새 Texture2D/Sprite를 만들고 컴포넌트 참조만 바꾼다.
게임의 AssetBundle, 원본 공유 텍스처, 버튼 동작은 수정하지 않는다.
삭제는 카탈로그에서 항목을 제거한 뒤 새 manifest를 배포한다. 캐시에 남은 미참조 PNG는 표시하지 않는다.
전체 이미지 기능을 해제할 때도 `entries: []` 카탈로그를 배포한다.

## 지원 범위

- `UnityEngine.UI.Image`의 sprite/overrideSprite: 원본 rect 크기·pivot·border·pixelsPerUnit 유지.
- `UnityEngine.UI.RawImage`의 texture: 전체 UV `(0,0,1,1)`만 지원.
- PNG, 최대 4096×4096, 파일당 8 MiB, 카탈로그 최대 256항목/64 MiB.
- Sprite atlas 안의 개별 Sprite는 지원한다. 전체 atlas 교체, UV 부분 영역 RawImage,
  custom shader/mesh, 영상, Spine/Live2D 등의 지원은 주장하지 않는다.

지역 카드 파일은 `BtArea01`~`BtArea06`의 396×396 Sprite다.
`tools/build_region_images.py`는 추출한 원본과 한국어 폰트를 입력받아 지명 영역만 교체한다.
그 밖의 모든 RGBA 픽셀이 원본과 동일한지 검사하며 폰트 파일은 배포하지 않는다.
시작 화면·회상 로고도 위 UI 유형과 대상 식별 조건을 만족하면 같은 카탈로그로 확장할 수 있다.
각 로고의 실제 표시 유형과 교체 이미지는 별도 확인 대상이다.

## 반영 절차

1. PNG와 대상 매핑을 검수하고 `images.json`을 작성한다.
2. 새 PNG는 `--add images/<hash>.png`, 카탈로그 변경은 `--modify images.json`으로
   `python tools/build_manifests.py translations/ko`에 전달한다. 최초 카탈로그는 `--add images.json`이다.
3. `python tools/verify_local_parity.py`와 package build를 실행한다.
4. 승인된 GitHub ref에 카탈로그·PNG·생성된 manifest를 함께 반영하고 게임을 재시작한다.

Novel/Names/Knowledge/HOLD 정본은 이미지 작성 도구의 수정 대상이 아니다.

## 시작/이벤트 로고 제작 기준

현재 이미지 시험은 사용자가 새로 제공한 `GirlsCreation_KO_MainLogo_RGBA.png`와
Codex 첫 번째 이벤트 시안을 사용한다. 앞선 두 번째 시안 선택을 대체한다.
시작 로고는 1536×652 RGBA 입력의 음영과 비율을 유지해 premultiplied-alpha Lanczos로
735×312로 축소한 뒤 원본 816×312 투명 캔버스 가운데 배치한다. 자르거나 획을 다시 그리지 않는다.
`opening_logo_r_01`만 대상으로 하며 일반판 로고는 포함하지 않는다.
`elg3335`의 「빛을 새기며」는 검수된 Master 제목과 같은 표기다. 첫 번째 생성 시안을
602×240으로 축소하고 x=20에 배치하여 원본 텍스처의 640×240 투명 캔버스를 복원한다.
이벤트 메인 `EventQuestView._logoImage`는 RawImage이므로 `kind: texture`로 등록한다.
같은 번들에 Sprite도 존재하지만 실제 표시 컴포넌트의 유형을 대신 판단할 근거는 아니다.
회상 목록의 캐릭터 포함 배너는 별도 자산이며 이 단독 로고 항목의 교체 대상이 아니다.
추출기의 Sprite.image는 잘린 textureRect 크기를 반환할 수 있으므로, 대상 크기는 반드시
원본 Sprite.rect로 확인하고 textureRectOffset에 해당하는 여백을 보존한다.
공방 `TitleAtelierResult`는 실제 사례로, 추출 PNG는 315×80이지만 Sprite.rect는 316×80이다.
315×80 매핑은 7.2.1 실기에서 적용되지 않았으므로 316×80 캔버스와 대상 키를 사용한다.

향후 이벤트 로고는 회상 탭의 작은 정보용 표시 크기에서 읽기 쉬운 제목을 우선한다.
원본의 색상·프레임·장식·배치를 최대한 살리되, 축소 후 획이 뭉치거나 부제 때문에
제목이 작아지지 않게 제작한다. 큰 원본뿐 아니라 실제 작은 화면에서 여백·대비·잘림을 확인한다.
생성형 재현으로 원본 픽셀이 달라졌다면 이를 원본 보존으로 기록하지 않는다.

## 회상 전체 확대판

첫 묶음의 DLL을 재검증한 뒤 36페이지의 추가 네 배너를 GitHub 자동 갱신으로 시험했다.
이 네 배너는 DLL 교체 없이 선택·페이지 이동·재방문에서 정상 표시되었다.
이어 현재 공개된 나머지 140개를 제작하여 회상 148개 전체를 등록했다.
미공개 후속 이벤트 네 개는 포함하지 않는다. 지역 카드 6개와 단독 로고 2개를 합하면
카탈로그는 156개 대상이며, 다른 홈/퀘스트 합성 카드 전체의 번역을 뜻하지 않는다.

전체 목록은 기존 128개 상한을 넘으므로 parser와 authoring validator의 상한을 256개로 맞췄다.
이미지는 최대 네 파일을 병렬 다운로드하며, 같은 PNG를 공유하는 대상도 모두 크기를 검사한다.
전체 검증이 성공한 뒤에만 새 카탈로그를 저장한다. 취소·해시 오류·잘못된 크기에서는 이전
카탈로그가 유지된다. Unity 객체 생성은 기존 표시 hook에서만 수행한다.
156개 cold-cache 갱신, 네 worker 상한, 공유 파일 검사, 취소 중 이전 목록 보존을 테스트했다.
전체 확대판 DLL SHA-256은 `7de9ee3f615214ab0767cbbf69317bf4f68dce7ec670e59035b2c85571bb9e2f`다.

제작은 built-in image_gen 원본 참조 편집과 제목 영역 한정 Pillow 합성을 사용했다.
140개 모두 제목 영역 밖 RGBA와 전체 alpha 보존을 검사하고 340×128 및 180×68로 검수했다.
생성 중 두 제목의 철자/중복 조사를 수정했으며, `ebs13120`의 피아는 Names 정본을 따랐다.
텍스트 Master/Names/Novel 정본은 변경하지 않았다. 프롬프트와 해시는
`docs/artwork/recollection-batch-02.json` 및 `recollection-batch-03.json`에 기록한다.
전체 목록의 GitHub 자동 갱신과 37페이지 실기 판정은 마지막 파일의 `native` 상태를 따른다.

2026-10-29 전체 확대판 실기에서는 새 PNG 140개를 설치 폴더에 복사하지 않고 GitHub에서 받았다.
첫 실행에 `Image data ready: 156 verified targets`가 기록되었고 설치된 목록/PNG의 해시도
저장소와 일치했다. 회상 1~37페이지의 148개 배너를 모두 화면으로 확인했으며, 홈 복귀 후
1·6페이지 재진입과 37페이지 이벤트 선택도 정상이다. 시작 로고·진행 중 이벤트 로고·지역 카드
6개도 재확인했다. 156개 대상 모두 교체 로그가 있고 해당 실행의 Error/Exception은 없었다.
AP/BP/코인/예정석 소비는 0이다. 기존 Il2CppInterop 경고까지 없애거나 모든 게임 동작을
검증했다는 뜻은 아니다. 이 검증 이후 사용자가 main 병합 및 공개 릴리스를 승인했다.

생성한 update ZIP은 기존 의존성이 있는 설치용이며 기본 CDN은 공식 main이다.
시험은 PR44의 ref에서 진행했으며, 공개 패키지는 main을 사용한다.
이 update ZIP을 신규 사용자용 전체 설치본으로 취급하지 않는다. 신규 설치에는 로더·Utility·
한국어 폰트까지 포함한 `GCMod-7.2.0-ko-full-win-x64.zip`을 사용한다.

## 시작 화면 문구 보완

접속 실패, 로그인 만료의 PC 문구, 캐시 삭제 안내와 진행 메시지, 유료 서비스 주의사항을
reviewed exact 사전에 추가했다. 캐시 안내는 `MlDictionaryTextConfigInApps`의 원문,
로그인 안내는 PC 코드 문자열, 주의사항은 공개 DMM 원문과 실제 TMP 표시 문자열을 대조했다.
주의사항의 공백·개행도 실제 표시값에 맞춰 저장한다. 문구 수집용 임시 플러그인은 배포하지 않는다.
추가 7개 항목은 UI 데이터 변경이며 DLL이나 Master/Novel 정본 변경을 요구하지 않는다.
주어진 코드가 삽입되는 별도 오류 메시지까지 포괄하는 범용 치환은 추가하지 않았다.

## 패배 안내 이미지와 최고 난이도 배지

7.2.1에서 사용하던 이미지 교체 경로에 패배 안내 `BattleEnhance_1`, `BattleDeck_1`,
`BattleGacha_1`의 1460×736 texture 3개를 추가한다. 카탈로그는 159개 대상이다.
원본 참조 image_gen으로 글자를 번역하고 텍스트 영역만 합성했다. 편집 영역 밖 픽셀과
원본 alpha를 보존했으며, 편성 안내의 상성 화살표도 원본을 유지한다.
사용자 지정 용어 `이마쥬`를 세 위치에 적용했다. 제작 프롬프트·원본 해시·마스크 검사와
실기 결과는 `docs/artwork/defeat-guides.json`에 기록한다.

레벨 부스트 +90의 `超高難易度！`는 PC 코드의 exact 문자열이며 `초고난도!`로 추가했다.
이 배지는 UI 데이터, 패배 안내는 PNG·매핑 데이터의 누락이었다. DLL·Master·Names·Novel은
변경하지 않으며 기존 시작 시 갱신으로 받을 수 있다. PR46 검토 브랜치의 변경으로,
공식 main 병합 여부와는 구분한다.
