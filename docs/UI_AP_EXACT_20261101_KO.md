# AP 시간·회복 문구의 데이터 추가 — 2026-11-01

사용자가 승인한 **DLL 업데이트 없는 완성 문장 생성 방식**으로 로컬 정본을 보완했다. 기준은 main `7c344e2aedee34da8c81e50791f356878ac40679`다.

| 대상 | 생성 범위 | 추가 수 | 번역 예시 |
|---|---|---:|---|
| `更新までHH:mm` | `00:00~12:00`, 양 끝 포함 | 721 | `갱신까지10:26` |
| `回数回復までHH:mm` | 같은 범위 | 721 | `횟수 회복까지 10:26` |
| `APをN回復しました。` | 정수 0~150, 양 끝 포함 | 151 | `AP를 107 회복했습니다.` |

총 1,593개를 추가해 `ui.json`은 11,975→13,568개가 됐다. 파일은 726,050→809,640 bytes로 83,590 bytes(약 81.6 KiB) 늘었다. 기존 키·번역값은 모두 보존했다. BP 회복이나 다른 시간 문구는 추가하지 않았다.

## 번역과 범위 근거

- 시간 문구 두 개의 `10:26` 표시는 사용자 사진에서 확인했다. AP 팝업의 설명은 12시간마다 회복 1회분이 충전된다고 명시한다. 이번 지원은 다음 충전까지의 0~12시간으로 한정한다.
- 확보된 popup 샘플은 `回数回復までhh:mm`이고, 현재 PC metadata에는 `hh\:mm`와 `{0:00}:{1:00}` 포맷이 존재한다. 두 자리 `HH:mm`을 생성하지만, 특정 포맷과 화면 producer의 직접 연결 및 한 자리 시간의 실기 표시는 아직 확인하지 않았다. `8:47`처럼 앞자리 0이 없는 표기는 범위에 넣지 않는다.
- `更新まで{value}`는 현재 `ui.templates.json`의 한국어를, `回数回復までhh:mm`는 기존 PRO 검수를 거친 `ui/general-exact.reviewed.json`의 한국어를 재사용했다.
- AP 회복은 현재 `master.json`의 `mTextConfig.ml_value[]`에 있는 `APを{0:#,0}回復しました。`의 한국어를 재사용한다. AP 0~150 범위는 사용자가 명시했다. 실제 수치 회복 알림의 화면 호출은 이번 작업에서 관측하지 않았다.
- 새 한국어 초벌이나 기존 문구의 의미 교정은 없다. 숫자·시간을 치환한 기술적 확장이며, 새 PRO 의미검수를 수행했다고 표시하지 않는다.

기존 실패 조회와 사진 hash는 [앞선 AP 조사](../staging/text-remainder-20261101/dynamic-ap-display-gaps.json)에 그대로 남겼다. 이번 결과로 과거 실패 기록을 덮어쓰지 않는다.

## 구현과 검증

기존 `tools/export_local_ui.py`가 `ui/ap-families.json`의 유한 범위를 읽어 `ui.json`을 생성한다. 원본 번역이 없거나 토큰이 달라지거나 기존 exact와 한국어가 충돌하면 실패한다. 기존 manifest 생성기를 통해 UI hash와 관련 metadata만 갱신했다. runtime source·DLL은 변경하지 않는다.

추가한 1,593개 전부를 현재 `UiTextLookup.cs`로 조회해 KO 일치를 확인했다. 범위 밖·잘못된 분·한 자리 시·BP·다른 시간 문구 11개는 계속 미일치다. 기존 조회 회귀의 63개 양성 사례와 29개 부정 경계, UI export 회귀 12개 및 package manifest 검사가 통과했다. 이전에 미지원이던 `更新まで08:47` 회귀는 지원 사례로 옮기고 `12:01`을 범위 밖 사례로 남겼다.

정본에서 바뀐 것은 `ui.json`과 관련 manifest 4개이며, 새로운 authoring 범위 파일을 추가했다. Master·Novel·Names·HOLD·Knowledge·runtime source·DLL·raw·기존 실패 근거는 유지한다. 게임 설치·실기 검증은 수행하지 않았으며 공개 반영 상태는 해당 PR 기록을 따른다. 병합 전 로컬 결과와 보호 파일 검사는 [verification.json](../staging/ui-ap-exact-20261101/verification.json)을 참조한다.

기존 8행 PRO 검수 ZIP은 그대로 보존한다. 이번 UI 갱신으로 batch의 package preimage가 달라졌으므로, 반환 시 8행 identity·JP·문맥이 유지됐는지 확인하고 현재 package 기준으로 배치를 다시 준비한 뒤 검수 결정을 가져와야 한다. 오래된 batch를 그대로 apply하지 않는다.
