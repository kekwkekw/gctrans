## 누락 원인과 수집 기준

앞선 전체 asset 취득은 Master와 prefab 등에 저장된 텍스트를 포괄했지만, 실행 코드의 문자열 상수는 별도 공급 경로다. 기존 PC literal 도구도 지정한 키워드만 수집했다. AP 완료 알림을 수치형 Master 문장으로 추정하고 코드 전체 inventory를 잔여 조사에 통합하지 않은 것이 이번 누락의 원인이다. PlayableDirector 추출 실패나 시간 문자열의 가변성 때문은 아니다.

`collect_ui_literals.py --all-japanese`를 추가해 현재 v39 문자열 테이블의 일본어 후보를 전체 수집할 수 있게 했다. 기존 `--contains`와 버전·offset 검증은 유지한다. 전체 선택에서도 로그/조각을 먼저 버리지 않고 raw hash와 index를 남겨 후속 분류한다. 수집을 넓히는 것과 번역 승인·현행 표시를 판정하는 것은 별도 단계다.

PC metadata 전체 literal은 21,952개이며 일본어로 보이는 문자를 포함한 고유 값은 1,567개였다. 기존 UI 조회 575개 성공, 992개 미일치다. 미일치는 실제 미번역 화면 992개라는 뜻이 아니다. 메타데이터 원본 hash는 `e311401192b2ef2fccd89fa73f70c38198149ae1c2df3c2b04eeeb714917f92a`이며 기존 AP 조사 때와 동일하다.

## AP 알림과 번역 재사용

사진의 `AP回復を実行しました`는 고정 문자열이다. `Gc.Museum.MuseumTopController+<TryOpenApRecoverPopup>d__10::MoveNext`에서 해당 literal과 `Gc.NotificationPopup::Create` 호출을 확인했다. PRO가 `AP를 회복했습니다`를 승인했고 정본 조회도 같은 결과다. 사용자 사진으로 일본어 표시가 확인된 유일한 항목이며, 한국어 적용 후 실기는 아직 하지 않았다. PR #55의 `APをN回復しました。` 0~150 확장과 별개다.
