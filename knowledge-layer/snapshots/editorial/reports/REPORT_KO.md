# Post-R36 PRO 문장부호·편집 정책 판정 보고서 v1.0

기준일: 2026-09-23  
성격: **사용자 수락 전 editorial 정책·국소 권고 패킷**. R36 대체 정본, 새 R37, 실행 가능한 changeset 또는 배포본이 아니다.

## 1. 완료 범위와 상태

이전 조사 22,859항목의 입력 계보를 확인하고, 말줄임표 10,500회에 대한 대응 정책·예외, 대시 1,027회의 문맥상 기능, 마침표 고우선 후보 20행, 공백 후보 40회와 국소 문장 경계 2건을 정리했다.

말줄임표의 일반 대응은 전체 구조 대조와 정책에 따른 분류이며, 10,500회를 모두 새로운 의미 검수 실적으로 세지 않는다. 원문 전체 재번역이나 R36/1,019건 의미 판정 재시작을 하지 않았다. 수동 예외 설명은 말줄임표 131회와 대시 86회, 합계 217회다. 이 목록은 전체 목록의 부분집합이며 중복 실적이 아니다.

R36의 의미 검수 707/707, Post-R36 사용자 결정 1,019/1,019, 기존 보류 12행, 원문 이상 13건은 그대로다. 이번 editorial 권고의 사용자 승인과 실제 적용은 모두 **아직 0**이다.

## 3. 말줄임표 정책과 예외

### 권고 정책

기본 glyph는 `…`(U+2026)이다. **실제로 대응하는 JP 말줄임표 run의 개수**를 보존한다. 원문이 `……`이면 `……`, `…………`이면 `…………`로 한다. 원문에 실제로 있는 1·3·5자 길이도 임의로 짝수로 만들지 않는다.

`......`을 무조건 `……`로 바꾸거나 점 개수를 3으로 나누어 반올림하지 않는다. 기존 의역으로 말줄임표 위치·개수가 달라진 경우에는 어구별 대응을 확인한다. 원문에만 있는 말줄임표를 이 glyph 통일 작업으로 새로 삽입하지 않는다. `<br>`와 줄바꿈 위치는 그대로다.

### 조사표의 “원문 ellipsis 없음” 5회

| 위치 | 실제 확인 | 권고 |
|---|---|---|
| 40106092/raw51 | JP/KO 줄 배치가 다를 뿐 전체 JP에 같은 쉼이 있음 | `......` → `……` |
| 40200742/raw103 | 같은 설명 어구가 다음 JP 줄까지 이어짐 | `......` → `……` |
| 20001402/raw45 | 예술이 전하려는 것을 말하는 어구의 줄 재배치 | `......` → `……` |
| 10010209/raw26 | 협박 발화가 다음 행의 공격으로 끊김. JP는 `――` | `......` → `――` |
| 99900001/raw27 | 기획서를 쓰려는 때 다음 발화가 끼어듦. JP는 `――` | `...` → `――` |

따라서 “비정상 말줄임표 5건”이라는 요약은 정확하지 않다. **3건은 줄 단위 분류의 한계, 2건은 부호 기능 복원 권고**다.

기존 contextual 81회도 전체 행에서 대응을 확인했다. 기존 aligned 분류 중 길이 불일치 35회는 개별로 확인했다. `10010406/raw40`처럼 JP에는 앞뒤 두 run, KO에는 뒤쪽 하나만 남은 경우에는 해당 뒤쪽 run에만 연결하며 앞쪽 쉼을 새로 만들지 않는다.

### 전체 분류

- 기존 말줄임표 glyph 통일 권고: **10,489회**
- 대시 기능 복원 권고: **2회**
- 원문 이상 위치 보호: **9회**
- 합계: **10,500회**

위 수는 정책상 분류다. 태그·괄호·원래 block/span과 최신 기준본 재대조 등 생성 전 보호 조건을 통과한 최종 변경 수는 다음 changeset 단계에서 계산한다.

## 4. 대시와 발음 늘임/효과음

### 권고 정책

서술의 삽입·연결·전환, 발화의 중단은 `―`(U+2015)를 사용한다. JP의 `――`, `──`, `——`는 **구조 기능이 확인된 경우에만** 같은 glyph 계열로 정리하고 JP run 개수를 보존한다. 실제 긴 구조용 run을 전부 2자로 줄이지 않는다.

한국어의 발음 늘임, 외침, 의성어는 이번에 바꾸지 않는다. `---`가 몇 자냐는 이유만으로 구조 대시라고 판단하지 않는다.

### 기존 자동 분류에서 추가로 보호한 5회

| 위치 | 기존 KO | 판단 |
|---|---|---|
| 40112101/raw49 | `보여주라고------!` | 낚시 중 외치는 소리의 늘임. 그대로 보존 |
| 10010801/raw34 | `바-------------------------------------앙!` | 충격 효과음. 그대로 보존 |
| 10010801/raw71 | `바-------------------------------------앙!` | 충격 효과음. 그대로 보존 |
| 10010804/raw33 | `아-------------------------` | 길게 지르는 소리. 그대로 보존 |
| 10010110/raw14 앞부분 | `그, 그러---니까------`의 `---` | 어중 발음 늘임. 앞부분만 보존 |

마지막 혼합형의 최종 권고는 **`그, 그러---니까――`**다. 앞의 발음 늘임은 유지하고 끝의 끊김만 구조 대시로 구분한다.

`20002804/raw25`도 원문 전체에는 구조 대시가 있으므로 줄 재배치 때문에 발생한 미분류를 보완했다.

### 전체 분류

- 구조 대시 glyph 통일 권고: **963회**
- 발음·외침·효과음 보존: **62회** (이전 57회 + 추가 5회)
- 원문 이상 위치 보호: **2회**
- 합계: **1,027회**

앞 절의 말줄임표→대시 2회는 이 1,027회에 새로 합산하지 않는다. 원래는 ellipsis 조사 목록에 있던 별도 발생이다.

## 5. 마침표 20행과 국소 경계 2건

### 서술문 종결 20행

19행에는 마침표 `.`를 하나 추가하도록 권고한다. `40106032/raw20`은 다음과 같이 **물음표 `?`**를 권고한다.

> 그녀의 진의는 어디에 있는걸까?

한국어 서술자의 자문형 문장이므로 JP가 `。`로 끝난다는 이유만으로 점만 기계적으로 붙이지 않는다. 이 권고는 해당 1행에 한정된다. 다른 문장과 대사 전부에 물음표나 마침표를 강제하지 않는다. `있는걸까`의 띄어쓰기도 이번 국소 부호 수정으로 조용히 바꾸지 않는다.

대사 끝 마침표 생략 관행, 기존 `!?` 순서·개수, 제목 부호는 유지한다. 독립 서술문 후보만 다룬다.

### 추가 국소 경계 2건

1. **99900001/raw3**  
   `경영이 어렵다<br>예술가들은` → `경영이 어렵다.<br>예술가들은`  
   두 개의 완결된 서술문이므로 첫 문장 끝에도 점이 필요하다. `<br>`는 유지한다. 같은 행의 맨 끝 마침표 후보와 다른 구간이다.

2. **40112062/raw122 — 상속 편집 이슈**  
   `기뻐했다.\n고 들었다.` → `기뻐했다고 들었다.`  
   문장·줄 경계로 잘린 전언 표현만 연결한다. 실제 JP의 마지막 “그렇게 들었다”라는 전언 성격을 유지한다. 승인된 메나르 이름 교정은 바꾸지 않는다. 이전 메모에 함께 적힌 R21-M012는 별도 raw124의 교정이므로 이번 수정 범위가 아니다.

두 번째 권고는 일반적인 줄바꿈 삭제 규칙이 아니다. 이 한 위치에서만 명시적으로 허용할 국소 권고다. 실제 실행 대상은 승인된 의미 기준본의 해시와 원래 block/span에 다시 연결해야 한다.

## 6. 공백 40회

닫는 인용부호나 말줄임표와 바로 이어져야 하는 부호 사이의 공백 **10회만 제거**를 권고한다. 나머지 **30회는 문장 경계, 앞선 발화 뒤 새 머뭇거림, 말더듬, 쉼의 분리를 위해 보존**한다.

예: `"이런거" !?` → `"이런거"!?`는 국소 권고다. 그러나 이미 `?`나 `!`로 끝난 문장 다음에 오는 새 `......` 앞 공백을 전부 없애지 않는다.

기존 조사 파일 기준 제거 목록은 **1, 3, 4, 11, 13, 14, 15, 17, 18, 39행**이다. 상세 원문·기존값·권고·이유는 `records/SPACING_RECOMMENDATIONS_40.jsonl`에 있다. 전역 정규식 공백 정리는 허용하지 않는다.

## 7. 보호 표시에 대한 정정

조사 파일에서 `source_anomaly=false`였던 발생 중 실제 기준본의 원문 이상 위치와 겹친 것이 **11회, 서로 다른 7개 위치**였다. 말줄임표 9회와 대시 2회다.

이 패킷은 원문 이상 13건의 판정을 변경하지 않고, **기존 정본의 ID/위치가 조사표의 boolean보다 우선하도록 보호 분류만 보완**했다. 잘못 표시된 조사 원본은 증거로 그대로 보존했다. 실제 11회는 변화 없는 보존 레코드로 기록했다.

- 기존 보류 12행의 본문은 읽기 패킷에 넣지 않고, 위치만 보호한다.
- 원문 이상 13개 위치는 자동 editorial에서 제외한다.
- raw 단위 괄호 불균형 48개 위치는 원래 묶음·이웃 raw의 확인 없이 자동 마감하지 않는다. 괄호를 자동 생성하거나 삭제하지 않는다.
- 태그 syntax/attribute와 click/ruby 내부는 제외한다. 태그 밖 문구는 원래 태그열·필드·span 불변을 증명한 경우만 후속 changeset에 넣는다.
- 같은 raw에 태그가 있다고 전체 행을 삭제하거나, `<br>`를 보통 공백으로 합치지 않는다.
- 원문 exact key, 기존 observed, 원래 whole_hand_block preimage, 기존 승인 레코드는 그대로다.

## 8. 검증과 한계

정책상 변경 권고 11,486구간을 가상 합성한 결과는 9,056개 서로 다른 행이다. 이는 **실행 가능한 changeset이나 최종 적용 수가 아니다.** 생성 전 태그·묶음·block/span·published baseline 재대조 조건이 남아 있다.

가상 합성에서:
- 선택 구간 겹침 0
- 단어·이름 등 부호/공백 외 문자열 동일
- 태그열 동일
- 괄호 기호열 동일
- 보류/원문 이상 행 변경 0

`verify_policy.py`는 자체 원본 조사 ZIP과 권고 레코드를 다시 대조하는 읽기 전용 검사기다. 최초 본 검사 40개와 오류 주입의 목표 검사 탐지 14개를 실제 수행했다. 최종 봉인 manifest 검사와 별도 재추출 검사 결과는 외부 validation JSON을 우선한다. 미실행 검사를 PASS로 채우지 않는다.

처음의 일반 Python 실행에서 이 작업과 무관한 spreadsheet 자동 warmup이 stderr를 출력했다. 그 실행을 “오류 출력 없음”이라고 세지 않았다. 이 검증기는 표준 라이브러리만 사용하므로 site-startup을 끄는 `python -S -B`로 실행해 분리했다. 원인·원출력은 `audit/EXECUTION_NOTES.json`에 보존했다.

HTML 열람 테스트 결과는 `audit/HTML_TESTS.json`의 실제 결과를 따른다. Windows, 게임 runtime, GCMod 폰트·줄바꿈·타이핑 속도는 시험하지 않았다. U+2026/U+2015로 바꾸면 코드포인트 개수·폰트 모양·줄바꿈·타이핑 진행에 차이가 날 수 있다. 이번 판단이 기존 화면과 동일한 타이밍을 보증하지 않는다.

## 9. 다음 단계

사용자가 이번 정책과 국소 예외를 수락한 뒤 **매우 높음으로 안전한 editorial changeset을 한 배치로 생성**한다. 정책 수락은 export·commit·GCMod·배포 허가가 아니다.

후속 작업은 아래 순서다.

1. 이 패킷과 의미 기준본의 해시·사용자 수락 범위를 고정한다.
2. 실물 원래 block/field/span, 태그, raw 묶음, 보류·원문 이상 제외를 검증한다. 권고에 적힌 effective row offset을 실제 production offset처럼 사용하지 않는다.
3. 의미 변경 뒤의 effective baseline을 전제로 editorial preimage를 만들고, 충돌 없는 변경만 기록한다. 사전 기준과 어긋나면 중단하고 해당 위치만 확인한다.
4. 원문·관찰형·역사적 proposal을 덮어쓰지 않고 파생 changeset과 미리보기·검증을 저장한다.
5. 실제 export 단계에서는 별도 허가 아래 최신 published baseline을 확인한다. 로컬 RC1과 현재 remote가 같다고 가정하지 않는다.

새 의미 쟁점이 없다면 추가 PRO 전수 검수는 필요하지 않다. 정책 또는 연출에 이견이 생긴 위치만 제한적으로 재판정한다.
