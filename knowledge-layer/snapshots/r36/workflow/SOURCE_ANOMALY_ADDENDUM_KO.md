# 원문 이상 대응 추가 운영 지침 — R30부터 승계

사용자가 R29 원문 진단 논의 뒤 추가를 승인한 운영 지침이다. 기존 의미 QA·원문 보존·승인·문장부호·보류·게시 지침을 대체하거나 완화하지 않는다. knowledge/policies의 승인 정책을 새로 추가하거나 schema status enum을 확장하는 변경이 아니다.

## 구분
1. 매우 유력한 원문 오기: source anomaly에 원래 문자열과 문맥상 의도 후보·근거·확신도를 남긴다. JP exact source/key는 보존한다. 기존 한국어가 의도된 문맥에 부합하면 오타의 문자 뜻으로 역교정하지 않는다. 새 번역이나 전역 교정의 자동 승인은 아니다.
2. 문맥과 충돌하지만 교정 방향이 확정되지 않은 원문: unresolved source contradiction으로 별도 기록한다. JP·observed·기존 proposal을 자동으로 뒤집지 않고, 독립적인 한국어 오역으로 중복 계산하지 않는다.
3. 문체상 어색함·중의성·전달 방식의 불명확함: 원문 오류로 단정하지 않는다. 기존 semantic QA에서 가능한 의미 범위와 불확실성만 기록한다.

원문 진단 전에 raw 원본, mapping, 화자, span/join, 제목 추출을 확인하여 추출·정렬 결함을 원문 오기로 오인하지 않는다. 수집 원본에서의 이상과 현재 공식 게임의 오류 확정은 별개다. 새 공식 원문·runtime을 확인하지 않았다면 확인했다고 기록하지 않는다. 이후 공식 원문이 갱신돼도 구버전 key를 조용히 덮지 않고 버전·해시·결정 이력을 남긴다.

## 별도 레이어와 현재 처리
source anomaly는 번역 finding/proposal, 명칭 conflicts, 민감 내용 deferred, punctuation/editorial issue와 별도다. 연관 ID는 연결할 수 있으나 수량·승인·완료 상태를 합치지 않는다. anomaly를 대조하고 기록하면 해당 행의 의미 1차 검수는 완료일 수 있지만 원문 문제 해결·번역 최종 수락·배포 완료를 뜻하지 않는다. 불명확한 원문에 맞춰 존재하지 않는 줄거리·주체·사실을 만들지 않는다.

현재 R29-SRC001(20003106/raw2)은 위장 방향의 문맥 충돌로 unresolved 유지한다. R29-SRC002(20003306/raw18)의 固体/個体는 유력 오기 진단을 유지하며 한국어 개체를 고체로 역교정하지 않는다. 이 메모는 두 건의 최종 판정이나 기존 레코드 수정이 아니다.

## 최종 판정과 향후 순서
R22~R36 의미 QA → source anomaly 최종 판정 및 의미 proposal 수락/기각 → 최신 의미 baseline 확정 → 별도 punctuation/editorial pass → 명시된 배포 절차의 export 순서로 진행한다. 이 순서는 작업 계획이며 지금 실행 완료됐다는 뜻이 아니다.

최종 판정 때 의도가 충분히 명확하면 근거를 명시한 intended-meaning 한국어를 채택할 수 있다. 공식·문맥 증거로 방향이 확인되는 경우에도 명시적 승인 결정과 이유가 필요하다. 여전히 불확실하면 원문에 충실하게 유지하거나 추가 확인이 필요한 미결로 남긴다. reviewer confidence만으로 승인하지 않는다. JP exact key와 원본/observed는 어떤 경우에도 그대로다.

Main M1과 이후 산출물의 교정 baseline은 실행 당시 최신 approved/published 자료다. R21 observed에서 Main M1을 다시 만들지 않는다. 이미 채택한 의미·제목·태그 결정을 보존하고 <click>, <ruby>, <br>, 분기·경계도 유지한다. 지금 GitHub·runtime·배포·전체 정규화는 수행하지 않는다.
